# Experience as an interactive git log

The owner approved a prototype (vanilla JS + CSS, Spanish only): `<scratchpad>/demo/gitlog.html` (absolute path given to the executor). Port it to the home page, bilingual, replacing the current Experience section on `/en/` and `/es/` (section id stays `experience` so nav and pager keep working).

## Behaviour to keep
- View switch `Terminal | List`. List = every job as a readable card (company, dates, role, metric, bullets, stack). List is the server-rendered default content so the page is crawlable and works without JS; JS enhances to the terminal view (decide default view: terminal when JS runs, list without JS).
- Left: commit graph newest→oldest, `lead:`/`feat:` prefixes, overlapping jobs on a side branch (fork + merge curves), `HEAD → main` on the newest, short sha per job, hover preview card (desktop only).
- Right: terminal with typed output, clickable tokens (sha/company → `git show`, tech → `grep`), Tab/→ completion with ghost text, ↑↓ history, Ctrl+L, typo suggestion, contextual suggestion chips (always include `download cv`).
- Commands: help, git log, git log --lead, git show <co>, git diff <a>..<b> (role change, + gained / − dropped / kept techs, years between), grep <tech>, git blame <tech>, git checkout <year>, git shortlog, whoami, ls, cat README.md, contact, history, sudo hire carlos, download cv / curl cv (real link to `/CarlosMontoya_CV_EN.pdf` or `_ES.pdf` by locale), clear.
- Boot: first time the terminal is on screen it types `cat README.md` then `git log --lead`; once; never with reduced motion (README only).
- Achievements (5) with toast + counter; once each.
- Command names stay in English (they are git); all prose, help text, errors, labels and README bilingual. Spanish copy from the prototype; write the English copy.
- Data from `src/data/experience.json` (visible entries only, bullets/title/date/metric per locale). Contact data must match `src/data/contact.json` (no phone). The years claim stays "18+".

## Integration
- New `src/components/astro/CareerLog.astro` + external client module(s) in `src/scripts/` (no inline scripts: CSP is enforced; `npm run build` runs the dist hash check and must pass without adding hashes).
- Link with the skill decks (already on main, `src/components/astro/Skill.astro` + `src/scripts/skill-decks.js`): `grep <tech>` / `git blame <tech>` highlight the matching card(s) in the decks (dispatch a CustomEvent, e.g. `skills:highlight`, that the decks listen to; decks bring the card to the top of its pile and pulse it; a "ver en el stack / see in stack" link scrolls to `#skills`). Conversely, clicking a card's tech name in the decks may run `grep` — optional, only if simple.
- Keep `src/components/react/Experience.jsx` in the repo if anything else imports it (the game does); only the home pages switch to CareerLog. Update/replace page-level tests that assert the old Experience markup.
- Tokens/themes: use existing tokens; terminal colours readable (AA) in light and dark; pixel font only for titles (no accented glyphs).
